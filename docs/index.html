Features

See the fleet. Open the evidence.

Follow a warning from the fleet dashboard to the affected service, package, or log entry.

01 / Fleet dashboard

Find the servers that need attention.

See CPU, memory, load, disk space, inodes, services, and incidents across the fleet. Filter by health, search by host, and sort by any resource metric.

  • Import a static Ansible inventory in INI, YAML, or JSON.
  • See when a reading is stale, unavailable, or still pending.
  • Keep polling from the menu bar after closing the window.

02 / OS vulnerabilities

See which packages need an update.

Cyberbot checks installed packages against critical advisories for supported Debian and Ubuntu releases. A new finding opens an incident and can trigger a macOS notification.

  • Search the fleet-wide catalog by CVE, package, or server.
  • Compare installed and fixed versions and check APT availability.
  • Copy an upgrade command for one or several eligible findings.

03 / AI investigations

Investigate incidents and review changes.

Use your installed Codex or Claude CLI to investigate a server, incident, or incident group. Each run has a fixed server scope, and the agent requests diagnostics through Cyberbot’s MCP gateway.

  • Review the exact command and target before approving a change.
  • See pending requests, results, and supported rollback options.
  • Run monitoring, vulnerability checks, and incident rules independently of AI.

How it works

From an SSH check to an incident.

Cyberbot runs a Python collector on demand from the remote account’s cache. Collection needs no always-running daemon, extra listening port, or hosted backend.

  1. 01

    Connect

    Cyberbot schedules the check and connects with OpenSSH using verified host keys.

  2. 02

    Collect

    The collector reads metrics or logs and returns a bounded, structured result.

  3. 03

    Evaluate

    The app saves observations locally and evaluates monitoring rules.

  4. 04

    Surface

    The dashboard shows fleet health and keeps the evidence behind each incident.

Optional AI investigation

Your CLI provider may process evidence included in a run. Cyberbot checks the server scope and asks for your approval before running an allowed action that changes a server.

Before you connect.

Find more detail in the setup and platform guides.

Read the user guide ↗
Do I have to install an agent on my servers?

Cyberbot copies a Python collector to ~/.cache/cyberbot in the remote account and runs it over SSH when a check is due. No Cyberbot daemon stays running on the server.

Does my data leave my Mac?

Monitoring data is stored locally. Cyberbot connects over SSH, downloads public package advisories, and probes a public host on TCP port 443 to check its internet connection. If you use AI investigations, your CLI provider processes evidence included in the run.

Do I need an AI subscription?

Monitoring, incidents, vulnerability checks, and custom checks run without a model. Optional AI investigations use your own CLI login.

Can the agent change my servers on its own?

Actions with side effects need your approval for the exact script and target. Cyberbot applies its action policy after you approve.

Which Linux distributions are supported?

Resource metrics work on Linux hosts with Python 3.5 or later. Service status needs systemd, and package advisories cover supported Debian and Ubuntu releases. See the Linux coverage matrix.

Is there a version for Windows or Linux desktops?

Cyberbot is currently a macOS desktop app that you build from source.
